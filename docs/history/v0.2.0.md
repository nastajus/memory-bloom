# Memory Bloom 0.2.0 — process interaction pass

- Date: 2026-10-23 09:50 America/Toronto
- Commit: [`28545cf`](https://github.com/nastajus/memory-bloom/commit/28545cf)
- Evidence status: reconstructed from the conversation and commit; no distinct executable or screenshot survived.

## Reported problems

- The complete title bar needed to respond to a simple click without preventing ordinary dragging.
- A title-bar click needed to toggle compact/detailed modes.
- Double-clicking a process needed to bring that app to the foreground.
- Right-click actions needed to duplicate focus/end-process functionality.
- Collapsing Firefox and other process branches was ineffective because each refresh reopened the tree.
- Firefox process descriptions needed to be more useful, with tab-title extraction investigated separately.

## Implementation

- Distinguished a stationary pointer release from a drag gesture.
- Made the compact surface and detailed title bar toggle modes on a simple click.
- Added process double-click focus and dark-context-ready focus/end actions.
- Captured group and process expansion state before rebuilding the tree, then restored it afterward.
- Refined Firefox process-role descriptions and exposed the current Firefox window title where available.

## Challenge and decision

The refresh bug was not a Firefox behavior: rebuilding WPF `TreeViewItem` instances discarded their expansion state. Persisting state by stable group name and PID fixed it without stopping live refreshes.
